# HW9搜尋算法

test.py可測試個問題的算法解答是否正確

## 1. 老鼠走迷宮（DFS）

狀態是老鼠的格子座標，動作是上右下左移動。遇到岔路選一個方向走到底，撞牆或進死路就回溯換方向，直到走到起司。程式有遞迴版與 stack 迭代版。
結果：找到 50 步的路，BFS 最短是 42 步，所以 DFS 只保證找到路、不保證最短。

## 2. 狼羊甘藍菜過河（BFS）

狀態是 `(農夫, 狼, 羊, 甘藍菜)` 各在左岸(0)或右岸(1)，農夫每次可空手或帶一樣東西過河。狼與羊、羊與甘藍菜在農夫不在時同岸就是非法狀態，直接丟掉。每次過河成本相同，所以 BFS 第一次到達 `(1,1,1,1)` 就是最少步數。
結果：最少 7 步。

## 3. 八皇后（DFS + 回溯）

一列放一個皇后，逐列用 DFS 選位置。用「行、`r-c`、`r+c`」三個集合檢查衝突，有衝突就剪枝；某列放不下就回溯上一列重選。解固定在深度 8，DFS 只需保存目前這一條路徑，比 BFS 省記憶體。
結果：共 92 組解，扣掉旋轉鏡射是 12 組基本解。

## 4. NPC 搜尋玩家（A*）

地圖有牆與沼澤（成本 3），NPC 可 8 方向移動（斜走成本 √2、不切牆角）。A* 用 octile 距離當 h(n)，優先往玩家方向展開。玩家移動時，NPC 每回合只走下一步並重新跑 A*。
結果：A* 展開 56 個節點，Dijkstra（h=0）要 81 個，路徑成本都是 25。

## 5. IC 電路繞線

把佈線區當格子圖，導線是兩個接腳間的路徑，障礙是巨集方塊。

**單一線網**
- **Lee 演算法**：BFS 波前擴展再回溯，保證最短。
- **A\* 繞線**：Lee 加 Manhattan 啟發函數，一樣最短但展開更少（28 格 vs 112 格）。
- **DFS 繞線**：找得到路但很繞（線長 40 vs 12），只當對照。
- **最少轉彎**：Dijkstra，狀態加入方向、轉彎加罰分，因為轉彎對應通孔，越少越好。

**多線網**
- **依序繞線**：一條一條繞，先繞的會擋住後繞的，結果取決於順序（本例 24 種順序只有 2 種全通）。
- **拆線重繞**：某條線繞不過去，就拆掉一條已繞好的線，先繞被擋的，再重繞被拆的，兩條都成功才保留。本例 4 條線全部繞通。

## 我的理解

DFS：一直往深處走，走不通就退回去換路，像走迷宮一樣。優點是省記憶體，缺點是找到的路不一定最短。
BFS：一層一層往外找，所以第一次找到目標，就一定是最少步數。
A*：每次先挑「已經走的距離加上估計還剩的距離」最小的點。因為有朝目標方向估計，所以比盲目亂找快。
