# HW1：2^n 的四種寫法與效率比較（power2n.py）

對應 Issue #3，檔案：`power2n.py`，測試用 `n = 100`（也可以 `python power2n.py 1000` 自己指定 n）。

## 我對這支程式的理解

同一個 2ⁿ 有四種寫法，差別全在「怎麼重複」：直接呼叫內建運算子、遞迴呼叫兩次、
遞迴呼叫一次、以及遞迴加查表。四種都必須處理基本情形 `n == 0` 回傳 `1`，否則會無限遞迴。
主程式用 `bench()` 逐一測試四個函式，量測每次呼叫的耗時、自動決定重複次數，
並核對答案是否等於 `2**100`，把差異攤在同一張表上比。
時間複雜度排序：**方法 1 < 方法 2b < 方法 3 ≪ 方法 2a**（2b、3 都是 O(n)，但 3 有查表開銷）。

**1. `power2n_builtin(n)` — 方法 1：內建冪次 `2**n`**

一行 `return 2 ** n` 就好。CPython 在底層用優化的整數冪次實作（位元左移），
O(1)、只要呼叫 1 次，實測 0.3 微秒完成，比遞迴快約 50 倍，是四種裡最快的。

**2. `power2n_double(n)` — 方法 2a：遞迴（雙倍呼叫）**

`return power2n_double(n - 1) + power2n_double(n - 1)`，每一層都往下呼叫兩次，
呼叫次數 2ⁿ − 1，時間複雜度 O(2ⁿ)。n = 100 時需要
`2^100 - 1 = 1.268e+30` 次呼叫，以實測速率 7.643e+06 次/秒外推要跑 **5.255e+15 年**
（宇宙年齡才 1.4 × 10¹⁰ 年），所以程式對它加了「呼叫次數上限 2,000,000」的保險，
超過就丟出 `CallLimitExceeded` 中斷，並用實測到的呼叫速率去外推總耗時，
避免主程式永遠卡住。主程式另外用小 n（8 ~ 21）實測它，可以看出每加 1，
耗時就 **剛好 ×2**（見下方執行結果的倍數欄），驗證了 O(2ⁿ) 的指數成長；
就算 n = 40（約 10¹² 次呼叫）也已經跑不完。

**3. `power2n_times2(n)` — 方法 2b：遞迴（單次呼叫）**

`return 2 * power2n_times2(n - 1)`，只往下呼叫一次，呼叫次數 n + 1、O(n)，
實測 13.8 微秒，很快也算得對。但遞迴深度就是 n —— Python 預設遞迴上限是 1000，
所以 n = 100 沒問題，n = 2000 卻會直接丟 `RecursionError`（同樣「出不來」，
可在執行結果最後兩行看到）。若要算很大的 n，可以用迴圈（迭代）
或提高 `sys.setrecursionlimit()`。

**4. `power2n_memo(n)` — 方法 3：遞迴 + 查表（memoization）**

程式碼和方法 2a「看起來幾乎一樣」，差別只在查表：第一次的呼叫真的會往下算，
第二次的 `power2n_memo(n-1)` 因為 `_TABLE[n-1]` 已經算過而直接命中回傳，
整棵 2ⁿ 個節點的遞迴樹被砍成一條只有 n 層的鏈，從 O(2ⁿ) 變成 O(n)、
呼叫次數約 2n + 1。實測 34.7 微秒，比方法 2b 慢一些，因為每層多做了查表
（dict 查找 + 寫入），但它示範了「遞迴 + 記憶化」的標準技巧。
和方法 2b 一樣會撞到遞迴深度上限 —— 查表省的是「計算量」，省不了「遞迴深度」。
`reset_table()` 會在每次量測前把 `_TABLE` 清回 `{0: 1}`，避免上一輪的結果干擾計時。

**5. `Counter` 與 `CallLimitExceeded` — 呼叫次數的保險**

每個函式第一行都呼叫 `counter.tick()` 累加呼叫次數，超過 `CALL_LIMIT = 2_000_000`
就丟出 `CallLimitExceeded`。這道保險是為了方法 2a 加的：沒有它，主程式會永遠卡在
1.268e+30 次呼叫裡。中斷時主程式會用實測到的呼叫速率去外推總耗時
（見執行結果中的「估算跑完 n = 100 需要約 …」）。

**6. `bench(fn, n, setup)` — 自動決定重複次數的計時器**

先單獨跑一次當基準，再依 `sample_time`（0.05 秒）反推要重複幾次
（`max_repeat` 封頂 100,000），把總時間除以重複次數得到「每次耗時」。
回傳 `(每次秒數, 重複次數, 結果值, 例外)`；例外（呼叫超限、遞迴溢位）
不會中斷主程式，而是被當成「失敗」印出來，繼續測下一個方法。

**7. `human_time()` 與 `sci()` — 時間與大數的格式化**

`human_time` 把秒數轉成微秒／毫秒／秒／分／時／天／年的人類單位；
`sci` 用 `Decimal` 把大到會讓 float 溢位的整數格式化成科學記號 ——
2¹⁰⁰ 這種 31 位數直接丟進 float 會 `OverflowError`。

**8. `main()` — 主流程**

先印出 `2^100` 的答案與位數，宣告四個方法的清單（名稱、函式、setup），
逐一丟進 `bench()`：成功就核對 `[OK]` / `[NG]`，失敗就印失敗原因；
接著估算方法 2a 的總耗時、跑小 n 的指數成長實測，
最後故意拿 n = 2000 去戳方法 2b 與方法 3，示範兩者都撞 `RecursionError`。
開頭的 `sys.stdout.reconfigure(encoding="utf-8")` 是為了 Windows 終端機的 cp950 編碼問題。
