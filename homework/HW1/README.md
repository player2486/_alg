# HW1：2^n 的四種寫法與效率比較（power2n.py）

對應 Issue #3，檔案：`power2n.py`，測試用 `n = 100`。

## 執行方式

```bash
python power2n.py        # 預設 n = 100
python power2n.py 1000   # 也可以自己指定 n
```

## 四種方法

| 方法 | 寫法 | 時間複雜度 | 呼叫次數（n = 100） | 結果 |
|------|------|-----------|--------------------|------|
| 方法 1 | `2**n`（內建冪次） | O(1)（底層位元左移） | 1 | ✔ 最快 |
| 方法 2a | `power2n(n-1) + power2n(n-1)` | O(2ⁿ) | 2¹⁰⁰ − 1 ≈ 1.27e30 | ✘ 跑不出來 |
| 方法 2b | `2 * power2n(n-1)` | O(n) | n + 1 = 101 | ✔ 但有遞迴深度限制 |
| 方法 3 | 遞迴 + 查表（memoization） | O(n) | 約 2n + 1 ≈ 201 | ✔ 也很快 |

四種方法都必須處理基本情形 `n == 0` 時回傳 `1`，否則會無限遞迴。

### 程式碼

```python
# 方法 1
def power2n_builtin(n):
    return 2**n

# 方法 2a：用遞迴（雙倍呼叫）
def power2n_double(n):
    if n == 0:
        return 1
    return power2n_double(n - 1) + power2n_double(n - 1)

# 方法 2b：用遞迴（單次呼叫）
def power2n_times2(n):
    if n == 0:
        return 1
    return 2 * power2n_times2(n - 1)

# 方法 3：用遞迴 + 查表
_TABLE = {0: 1}
def power2n_memo(n):
    if n in _TABLE:
        return _TABLE[n]
    value = power2n_memo(n - 1) + power2n_memo(n - 1)  # 第二次直接命中查表
    _TABLE[n] = value
    return value
```

方法 3 與方法 2a 的程式碼「看起來幾乎一樣」，差別只在查表：
第二次的 `power2n_memo(n-1)` 真的會往下算，第一次因為 `_TABLE[n-1]` 已經算過而直接命中回傳，
整棵 2ⁿ 個節點的遞迴樹被砍成一條只有 n 層的鏈。

## 實測結果（n = 100）

主程式會逐一測試四個函式，量測每次呼叫的耗時、自動決定重複次數，並核對答案是否等於 `2**100`：

| 方法 | 每次耗時（約） | 重複次數 | 是否算得出來 |
|------|---------|---------|-------------|
| 方法 1 `2**n` | **0.2 ~ 0.3 微秒** | 約 60000 ~ 100000 | [OK] 正確，最快 |
| 方法 2a 雙倍遞迴 | 無法完成 | -- | [NG] 超過 2,000,000 次呼叫即中止（耗時約 0.3 秒，連九牛一毛都不到） |
| 方法 2b `2*power2n(n-1)` | **15 ~ 17 微秒** | 約 2500 | [OK] 正確 |
| 方法 3 遞迴 + 查表 | **35 ~ 39 微秒** | 約 1000 | [OK] 正確 |

> 以上為本機（Windows / Python 3.14.3）實測值，不同機器會有差異，請以執行為準。

### 為什麼方法 2a 出不來

方法 2a 每一層都會呼叫兩次，呼叫次數為 2ⁿ − 1。n = 100 時需要

```
2^100 - 1 = 1,267,650,600,228,229,401,496,703,205,375  ≈ 1.27 × 10^30 次呼叫
```

本機實測速率約每秒 6 ~ 7 × 10⁶ 次呼叫，外推跑完 n = 100 需要
**約 5 ~ 7 × 10¹⁵ 年**（宇宙年齡才 1.4 × 10¹⁰ 年），所以程式對方法 2a 加了
「呼叫次數上限 2,000,000」的保險，超過就丟出 `CallLimitExceeded` 中斷，
並用實測到的呼叫速率去外推總耗時，避免主程式永遠卡住。

主程式另外用小 n（8 ~ 21）實測方法 2a，可以看出每加 1，耗時就 **剛好 ×2**
（實測倍數 1.92x ~ 2.07x），驗證了 O(2ⁿ) 的指數成長：

```
   n     呼叫次數        耗時     倍數
  18     262,143    89 毫秒      -
  19     524,287   174 毫秒  1.95x
  20   1,048,575   347 毫秒  2.00x
  21   2,097,151   864 毫秒  2.49x
```

### 另一個「出不來」：方法 2b 與方法 3 的遞迴深度

方法 2b 只呼叫一次，O(n) 很快，但遞迴深度就是 n。Python 預設遞迴上限是 1000，
所以 n = 100 沒問題，n = 2000 卻會直接丟 `RecursionError`（程式中另有實測）。
方法 3（查表）也一樣會撞到 —— 查表省的是「計算量」，省不了「遞迴深度」。
若要計算很大的 n，可以用迴圈（迭代）或提高 `sys.setrecursionlimit()`。

## 結論（哪個快、哪個慢）

1. **最快：方法 1**（`2**n`）— CPython 在底層用優化的整數冪次實作，0.3 微秒完成，比遞迴快約 50 倍。
2. **次快：方法 2b**（約 16 微秒）與**方法 3**（約 37 微秒）— 都是 O(n)，只做 n 次加法／乘法；
   方法 3 因為每層多做了查表（dict 查找 + 寫入），比 2b 慢一些，但它示範了
   「遞迴 + 記憶化」的標準技巧：程式碼和 2a 幾乎一樣，卻從 O(2ⁿ) 變成 O(n)。
3. **最慢且跑不出來：方法 2a** — O(2ⁿ) 指數爆炸，n = 100 需要 1.27 × 10³⁰ 次呼叫（約 10¹⁵ ~ 10¹⁶ 年）；
   就算 n = 40（約 10¹² 次呼叫）也已經跑不完。
4. **隱藏地雷：方法 2b 與方法 3** — 時間上都沒問題，但遞迴深度都是 n，
   n ≥ 1000 時會撞到 Python 的遞迴上限而 `RecursionError`，同樣「出不來」。

時間複雜度排序：**方法 1 < 方法 2b < 方法 3 ≪ 方法 2a**（2b、3 都是 O(n)，但 3 有查表開銷）。
