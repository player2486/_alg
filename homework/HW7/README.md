# Diff 演算法比較：LCS vs Myers' Algorithm

## 1. 動態規劃 (LCS)

**原理**：將兩個檔案視為序列，找最長共同子序列（LCS）。建立 M×N 矩陣，`dp[i][j]` 代表 A 前 i 行與 B 前 j 行的 LCS 長度：
- 行相同：`dp[i][j] = dp[i-1][j-1] + 1`
- 行不同：`dp[i][j] = max(dp[i-1][j], dp[i][j-1])`

填完表後，從右下角回溯即可得出刪除/新增路徑。

**複雜度**：時間 O(M × N)，空間 O(M × N)

## 2. Myers' Algorithm (非動態規劃)

**原理**：將比對轉為編輯圖上的最短路徑問題（右=刪除，下=插入，對角線=相同免費走）。以差異數 D = 0, 1, 2… 由小到大貪婪擴張，遇到相同內容就盡量走對角線，先抵達右下角的路徑即為最短編輯路徑。

**複雜度**：時間 O((M + N) × D)，空間 O(M + N)，其中 D 為實際差異行數

## 3. 兩者比較

動態規劃（LCS）無論檔案差異多少，都會固定填滿整個 M×N 矩陣，時間與空間都為 O(M×N)，即使兩個檔案幾乎完全一樣也不會加速；適合教學或短字串比對。

Myers' Algorithm 則依差異數 D 貪婪擴張，時間為 O((M + N) × D)，空間約 O(M + N)。檔案越相似，D 越小，執行越快；最差情況會退化為 O((M+N)²)，但可設定 D 上限提早中斷。它是 git diff 等版本控制系統的工業標準解法。

## 我的理解

實務上連續 Commit 通常只差幾行（D 遠小於 M、N）。LCS 會盲目遍歷整個狀態空間，而 Myers 利用「多數內容相同」的先驗假設大幅削減搜尋，這是它成為 Diff 標準解法的原因。
